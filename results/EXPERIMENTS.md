# Public Experiment Log

This log records development results on the released 200-session public set.
It is not evidence of performance on the organizer's 800 private sessions.

## Protocol

- Dataset: `data/public_set.jsonl` (200 sessions)
- Catalog: frozen 50,000-row `data/catalog.jsonl`
- Evaluator: unmodified `evaluator/local_evaluator.py`
- Runtime: Python 3.12.13 on the development Windows machine
- Dependencies: Python standard library only
- Model/API usage: none
- Reported prompt/completion tokens: zero
- Network and credential requirement: none

The public set was used repeatedly for diagnosis and tuning. It must therefore
be treated as development data rather than an untouched holdout.

## Held-out train / validation / test split

The 200 public sessions are the only labeled development data, but every
architecture decision above was made while looking at all 200 — reporting that
same population as a benchmark is "training on the test set". From now on the
set is carved into a reproducible, scenario-stratified split generated by
`scripts/make_splits.py` (ratios 0.6/0.2/0.2, seed `20260830`); see
`data/splits/README.md`.

| Split | n | Hit Rate@10 | MRR | MTTC | TechnicalScore | Artifact |
|---|---:|---:|---:|---:|---:|---|
| Train | 120 | 1.000 | 0.917361 | 2.075 | 0.953708 | [003](003_lexicographic_train.json) |
| Validation | 40 | 1.000 | 0.966667 | 1.975 | 0.970500 | [004](004_lexicographic_val.json) |
| Test | 40 | 1.000 | 0.841488 | 2.100 | 0.930446 | [005](005_lexicographic_test.json) |

All three were produced by the same code at commit `bd7452e` using an
unmodified evaluator (`--dataset`/`--output` only). Rules: tune on train, choose
between variants on validation, and run test exactly once as the reported
number.

Two caveats make even the test split optimistic rather than a private-set
estimate:

- **Prior contamination:** the architecture was already tuned against all 200
  sessions (including these 40 test rows) before the split existed, so the test
  number is a fresh measurement, not a pristine holdout.
- **Size:** 40 sessions means per-scenario slices are tiny (2 boundary, 6
  intent-override), so overall MRR is meaningful but per-scenario numbers are
  noise.

Current scenario Hit Rate@10 (full development set, overfit) is 1.0 for Buying, Browsing, Intent Override, and
Boundary. The complete output was byte-identical across two clean evaluator
processes (SHA-256 `7A3A43BF490FE4D985C11747A2B5F4BEC6058D84BCB429B46720A088574EC05D`).
One complete run took approximately 33.2 seconds including index construction
and all conversations. Eight focused unit tests pass.

Raw evaluator outputs are stored in this folder (`results/`) and named
`NNN_slug.json`; the convention and lineage rules are documented in
[`README.md`](README.md). The table above links each retained experiment to its
artifact.

## What produced the gain

1. Retaining category and disclosed constraints across turns fixed the
   starter's repeated stateless queries.
2. Mapping catalog-grounded evidence back to products recovered candidates
   when a constraint appeared close to verbatim.
3. Restricting exact evidence to the resolved category prevented generic
   values such as `Imported` from favoring unrelated products.
4. A small penalty for previously recommended candidates broadened exploration
   when a turn supplied no new evidence.
5. Boundary handling retires declined attributes, while a productive typed
   question can repeat once to obtain additional constraints of the same type.

## Limitations and overfitting risk

- Every public session was available during development; the final public score
  is descriptive, not an unbiased estimate.
- The official simulator frequently reveals catalog strings close to verbatim.
  Exact-evidence matching may degrade when a person paraphrases the same idea.
- The parser recognizes the evaluator's standard message markers more reliably
  than arbitrary natural conversation.
- Asking `other` is unusually productive in the public simulator and is less
  specific than a real shopping assistant should be.
- Hit Rate only requires the target to appear anywhere in Top 10. MRR below 1.0
  shows that the exact target is not consistently ranked first.
- Indexes are rebuilt for each clean process; persistence, cold-start memory,
  and peak-memory benchmarks remain future work.

## Generalization harness & robustness pass

A reproducible unseen-catalog harness now measures the agent on 400 catalog
targets that never appear in the 200 public sessions, plus a deterministic
paraphrase/reworded stress set (`scripts/make_unseen_sessions.py`,
`scripts/paraphrase.py`, `scripts/bench_generalization.py`). All runs use the
unmodified evaluator scoring; the custom loop self-checks equal to `evaluate()`.

Full 400 unseen sessions, verbatim:

| | Hit@10 | MRR | MTTC | score |
|---|---:|---:|---:|---:|
| baseline | 0.973 | 0.7747 | 2.462 | 0.8894 |
| after robustness pass | 0.975 | 0.7970 | 2.478 | 0.8971 |

Paired 40 unseen sessions (same targets):

| mode | before | after |
|---|---:|---:|
| verbatim score | 0.8844 | 0.9061 |
| paraphrase score | 0.6844 | **0.7730** |
| reworded score | 0.4068 | **0.7527** |

What changed (all in `starter/agent.py`, no evaluator edits):

- expanded material/color vocabularies fed into the typed index and parser;
- synonym normalization (`water-resistant` -> `waterproof`, etc.);
- larger function-word stop list so reworded constraints stop diluting the
  token-overlap ratio;
- parser no longer requires the evaluator's exact templates: category
  (`I need/want/like a ...`), requirement markers, override
  (`scratch that / changed my mind / instead`), and exploratory-reply skipping;
- emission gate keyed on *matched* coverage instead of declared constraint
  count (fixes a latent "I'm still exploring" evidence bug);
- query-relevance tie-break inside equal-coverage tiers (before the quality
  prior): +0.022 MRR on the full 400 unseen verbatim run;
- hedge/function-word stopwords (`if`, `possible`, `anyway`, ...): one extra
  word was diluting the 0.7 token-overlap ratio; on the 200 unseen attribution
  run this cut filler retrieval misses 32 -> 7 and lifted filler Hit@10
  0.755 -> 0.920 with no verbatim/typed/structure regression.

Attribution harness: `scripts/bench.py` + orthogonal axes in
`scripts/paraphrase.py` (`typed`/`synonym`/`filler`/`structure`) report, per
mode, the target-coverage histogram (zero/one/multi) and a per-session miss
classification (`parser`/`retrieval`/`ordering`) versus the verbatim run.

Takeaway: the public `0.952` was an overfit upper bound; the honest
generalization baseline is ~`0.897` verbatim and ~`0.77` under paraphrased
constraints. The robustness pass recovered most of the paraphrase cliff and
improved verbatim MRR, but the residual paraphrase gap (verbatim 0.897 vs
paraphrase 0.773) is the next target: a semantic/dense route or richer typed
features.

## Reverted experiments (lineage dead ends)

- **Partition-entropy typed clarifier** (parent 002, reverted): chose the typed
  attribute with the most distinct values over the current tier. On the public
  simulator `feature` is the evaluator's catch-all slot, so it picked narrower
  slots and regressed boundary MRR `0.910` to `0.785` (overall score `0.952` to
  `0.949`). Reverted to `other`-first then fixed typed order; no artifact
  retained.
- **FTS pre-filter for token overlap** (reverted): pre-filtered the O(3000)
  category scan with an FTS top-400 pass. Faster, but it lost recall and
  dropped paraphrase Hit@10 by ~0.025 on the unseen harness, so the exact scan
  was restored. A lossless speedup needs a token inverted index (memory cost),
  left as future work.
- **Profile-affinity tie-break** (reverted): added profile FTS affinity into the
  equal-coverage relevance tie-break. Measured exactly zero change on the
  unseen 40-session harness across verbatim/paraphrase/reworded, so it was
  removed rather than shipping dead weight.
- **Magnitude-based BM25 relevance** (reverted): replaced the rank-based
  `1/(60+rank)` relevance with raw `-bm25` scores. Long-document bias regressed
  typed MRR `0.722 -> 0.668` and verbatim Hit `0.980 -> 0.965`; rank-based
  relevance was restored.
- **Budget-proximity tie-break** (reverted): boosted products closest to
  `around $X`. Measured no-op on the unseen 200 (budget constraints are rare
  because price is missing on ~79% of the catalog).
- **Supervised 3-feature reranker** (dead end, not integrated): logistic
  regression over 31k top-tier train pairs on `[match_tier, relevance,
  quality]` found no usable signal (0.87% positive rate, near-chance weights).
  Conclusion: the ordering gap is an *information* gap (reworded constraints
  leave a wide, indistinguishable tier), not a weight-tuning gap.

## Next experiments

1. Generate protocol-compatible sessions for catalog targets outside the 200
   public targets to test unseen-product transfer.
2. Add a paraphrase stress set and measure the drop from exact catalog wording.
3. Accumulate materials, colors, brands, sizes, budgets, negations, and
   corrections from arbitrary customer sentences rather than fixed templates.
4. Compare the fixed question policy with category-grounded candidate entropy
   or expected information gain.
5. Improve ordering among products that share all disclosed evidence, targeting
   MRR without sacrificing Hit Rate or MTTC.
6. Benchmark persistent indexes, cold/warm latency, and peak memory before
   adding embeddings or an LLM reranker.
